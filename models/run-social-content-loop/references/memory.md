# Social content loop Memory

Use `<current-product-workspace>/memory/run-social-content-loop/` as this Model's persistent Memory. Never read or write another Product's Memory unless the user explicitly requests a comparison and the output owner is clear.

## Separation from SEO

Social content Memory may reference SEO Memory as evidence, for example a validated product page brief or query insight, but it must not store social campaign files under `memory/run-seo-page-loop/`.

Do not copy SEO reports into social Memory. Link the exact source path and restate only the claim, limitation, or product fact needed for the social decision.

## Before observation

Read entries relevant to the current platform, content topic, audience, feature, campaign, post URL, landing page, or review window. Recover product claim ledgers, platform research, content packages, reviews, publication records, metric windows, guardrails, and pending next actions.

Treat prior content judgments as time-scoped. Platform rules, public trends, and product capabilities may change.

## After observation, action, or review

Use date- or timestamp-prefixed readable files. A content package can be a subdirectory when it contains text, HTML previews, images, screenshots, CSV summaries, or platform-specific variants.

Make these facts recoverable:

- collection time, platform, market, language, topic, and access limits;
- product facts used, evidence sources, and rejected claims;
- public competitor/content sources and synthesized patterns;
- copyright, privacy, brand, compliance, and AI-trace review status;
- candidate list, self-review, selected candidate, and reason for rejection;
- visual package version, source tier, visual specification, manifest, prompt/model provenance, effect selection, correction record, mechanical validation, and final visual-review decision when cards were produced;
- publication mode: not published, human-assisted, draft API, or live API;
- publication URL or platform ID when available;
- link, UTM, landing page, campaign code, and attribution assumptions;
- platform metrics, product metrics, data-quality issues, and guardrails;
- decision and one recommended next action.

## Sensitive data

Do not write credentials, cookies, raw platform exports containing private account/user identifiers, private comments, direct-message content, unpublished platform tokens, or full row-level product events to shared Memory.

Shared Memory should contain redacted aggregates, source provenance, limitations, selected assets, final public content, and links to private retention paths chosen by the team.

## Keep methodology with its owner

Apply better loop sequencing or Memory practice to this Model. Apply better source access and export normalization to Collectors. Apply better creation, review, publishing, or task-specific performance methods to Executors.

Memory records what happened. It is not a backlog for method changes.
