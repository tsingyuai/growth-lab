# Idea starting path

Use this path when no current product artifact exists.

## Keep the boundary clear

Do not present product analytics, platform connection, publishing, or API Key setup. Do not claim Product activation, retention, or channel performance.

Use the current Product workspace's `SOUL.md` to record the idea as the current product form. Distinguish:

- user-stated problem, audience, and proposed solution;
- public evidence;
- Agent hypotheses;
- open validation questions.

Do not create a separate Product/Concept schema.

## Establish enough context

Recover or ask only for the problem, intended user and situation, proposed solution, material constraints, and the decision the user wants to support.

Prefer evidence that reduces the largest risk: problem existence, user specificity, current alternatives, willingness to change or pay, feasibility, then distribution.

Scan actual Models before promising a validation loop. When no Model covers idea validation, say so. You may establish SOUL and complete bounded public research or a Brief, but do not represent that as an implemented end-to-end Growth Lab capability.

When a prototype, repository, or live product later exists, update the Product form and verified capabilities in the same workspace's `SOUL.md`. Preserve timed idea-validation observations in the relevant Model Memory when a Model owns them.
