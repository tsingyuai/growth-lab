# 质量检查

## 渲染前

- `draft.md` 内容脚本已完整展示给用户；对应 `content-approval.md` 明确批准当前标题、卡片顺序、逐卡上图文字、CTA 和卡数。任一实质内容变化都会使批准失效并退回脚本审核。
- 内容脚本在不依赖视觉效果时仍然翔实有效：逐卡新增信息清楚、产品事实有证据、读者所得明确、整套内容能够独立讲完整。
- 标题、caption 和上图文字已完成 DAI。
- 宣称已对照当前产品证据。
- image plan 已审定，所需参考图与真实浏览器截图齐全。
- 每张产品能力卡已写明 `user_takeaway` 和精确 `evidence_target`；官网身份、Logo 或仓库首页不能代替功能证据。
- 合规和禁用表达脚本退出码均为 0。
- 生产模式与 image plan 一致；确定性渲染保留精确文字和真实截图，可分离图层不含文字或 UI，完整效果只使用已验证的单一视觉参考。
- 真实产品 UI、logo、引用和数据来自产品自有证据，没有把模型生成界面冒充真实截图。
- 已在生产模式选择前检查生图配置；配置可用且用户批准时，封面和视觉主导卡优先完成 API 效果探索。
- 若使用纯确定性渲染，已记录用户拒绝、配置不可用、任务纯结构化或生图无法增加有效视觉价值中的至少一个原因。
- API 生成的精确文字、真实 UI、logo、引用和数据已替换为确定性文字或产品自有证据，不把模型生成内容冒充真实证据。
- 有可用且获授权的生图 API 时，已先生成并比较 2–3 个完整效果方向；无 API 或用户拒绝时，已记录原因并使用经过验证的确定性版式。

## 逐图检查

以全尺寸打开每张最终图片，检查：中英文、数字、引用和标点逐字准确；卡片顺序与 image plan 一致；没有多余文字、水印、异常物体、假 UI 或虚构数据；截图中的产品名称、结构、关键文字和界面关系与源图一致；单图、多步骤流、局部特写或前后对比具有明确主次；裁切、标注、边距、对比和层级适合移动端；每个圈注在局部放大图中命中具体 UI 对象；参考版式没有复制受保护的正文或品牌；生成元素没有遮挡事实证据。

单卡失败时做一次针对性重生并重新检查。模型生成的文字或 UI 不准确时，保留已确认的整体效果，用 HTML、SVG、Canvas 或 Pillow 定点替换精确文字和真实证据；只有整体构图也失败时才拒绝候选。不得因为局部文字错误直接放弃已通过的视觉方向。

## 整帖检查

- 封面能吸引点击，但没有无依据承诺。
- 顺序从钩子走向场景、证据和有用结论。
- 不同卡片没有换装饰重复同一结论。
- `layout-ledger.json` 已通过且联系表中没有连续复用「标题 + 横向截图」骨架；脚本通过不能替代最终像素检查。
- caption 与卡片中的事实和术语一致。
- 产品身份与商业角色诚实清楚。
- 全文只有一个鲜明立场，没有客观综述、兼顾两面、退缩词或防御性表达。
- 有风险或无证据的 claim 已整句删除，没有通过免责声明保留弱化版本。
