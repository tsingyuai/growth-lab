## B. Card mapping

| # | Card role | User takeaway | Exact visible copy | Evidence target and real source | Screenshot composition and annotation target | Visual rule from primary | Production mode | Acceptance |
|---|---|---|---|---|---|---|---|---|
| 01 | Cover hook | I can understand... |  | exact UI/output + source path | single-hero + target object | hierarchy only |  | hook and proof readable in feed thumbnail |
| 02 | Method/value | I can do... |  | exact step/result + source path | step-flow + step targets | reading rhythm only |  | ordered steps are immediately understood |
| 03 | Product proof | I can verify... |  | exact changed state + source path | hero-plus-detail + detail target | proof-zone proportion only |  | evidence remains accurate and readable |

Normal modes do not map cards one-to-one merely because the reference has that count. `close-replication` intentionally maps the single primary reference card-by-card, including order and relative composition, while replacing all source text, images, logos, people, proprietary UI, illustrations, and brand assets.

For every screenshot crop, retain the uncropped source and record crop coordinates. When annotation is needed, record the concrete UI object, marker coordinates, label text, and magnified-review output. A homepage, logo, or repository identity is evidence of Product identity only.

## D. Layout ledger

Create `layout-ledger.json` before formal rendering. Record `archetype`, `title_anchor`, `visual_mass`, `reading_path`, `screenshot_geometry`, and `unique_move` for every card. A pack of three or more cards must pass `check_layout_variety.py` and a final contact-sheet review.

## E. Prompt requirements

For `separable-layer`, prompts must prohibit all text, logos, UI, documents, citations, statistics, and watermarks. For `complete-effect`, state the role of every reference and forbid copying the source identity or presenting generated Product UI as real. Deterministic cards must lock fonts, dimensions, copy source, screenshot crop, and output path.

## F. Pre-render checks

- [ ] Draft and every visible string passed DAI.
- [ ] Claims have Product evidence.
- [ ] Exactly one primary external visual reference is validated.
- [ ] Rejected candidates contribute no visual rules or model inputs.
- [ ] Product UI, logo, data, and citations use real owned evidence.
- [ ] Every Product capability card has a specific evidence target and real screenshot source.
- [ ] Multi-screenshot cards use a meaningful step flow, comparison, or primary-detail relationship rather than an equal filler grid.
- [ ] Annotation plans target concrete UI objects and will be bound to screenshot coordinates before composition.
- [ ] `layout-ledger.json` passes before full rendering.
- [ ] Card count follows content value, not the source sequence.
- [ ] Before the first provider image, the user chose API configuration or a deterministic/no-image alternative; configured credentials were verified without display.
- [ ] Paid generation has separate approval when used.
