## B. 逐卡映射

| # | 卡片职责 | 准确上图文案 | 参考/版式 | 真实素材 | 制作路线 | 验收标准 |
|---|---|---|---|---|---|---|
| 01 | 封面钩子 |  | 指定参考图 | 无/来源 | 参考图生图 | 信息流缩略图可读 |
| 02 | 场景/价值 |  | 指定参考图 |  | 参考图生图 | 只讲一个清晰结论 |
| 03 | 产品证据 |  |  | 真实截图 | 占位+贴图 | UI 像素不变 |

允许的路线只有两种：`参考图生图`，必须把对应来源图片传给仓库内生图 Client；`参考图生图 + 真实截图贴图`，用于当前产品的真实 UI、官网、代码、数据、引用或必须保持原样的浏览器截图。生图模型可以重绘不承担产品事实证据的网页视觉。禁止因为文字多、中英文混排、精确排版或网页重绘而改用 HTML、SVG、CSS、Canvas、PPT、模板引擎或代码绘制卡片。

## C. 素材清单

| 素材 | 来源 URL/路径 | 获取时间 | 使用卡片 | 隐私检查 | 状态 |
|---|---|---|---|---|---|
|  |  |  |  |  | 缺失/就绪 |

不得写入凭据或复制的平台正文。优先记录规范来源链接，而不是来源不明的下载文件。

## D. Prompt 要求

每张卡单独一个 prompt 文件，写明用途与构图、逐字准确的可见文字、配色、对应参考图路径、必须留空供真实截图贴图的区域，以及禁止水印、假 UI、虚构数据、多余文字或假 logo。执行命令必须实际包含至少一个 `--ref`。

## E. 渲染前检查

- [ ] 草稿和全部上图文字已通过 DAI。
- [ ] 宣称有当前产品事实支持。
- [ ] 每张卡提供不同的用户价值或证据。
- [ ] 参考映射明确，没有为了凑卡数硬对齐。
- [ ] 所有素材存在且来源可追溯。
- [ ] 每张卡的生图命令都包含确认过的参考图。
- [ ] 截图卡采用确定性贴图。
- [ ] 当前产品 UI、官网、代码界面和仓库页面来自真实浏览器截图。
- [ ] 没有 HTML、SVG 或其他代码模板渲染路线。
- [ ] 用户要求的确认点已通过。
